# 紅兵寫真旅拍引擎｜全站分類歸屬總規範

版本：v4.54
適用範圍：首頁、正式工具頁、選項資料、一鍵模板、風格範例與維護腳本。

## 1. 目的

本規範用來判斷一張參考圖、一段咒語或一個新模板應該歸入哪一個工具頁。分類的目的不是把素材貼上漂亮標籤，而是讓每個頁面只負責一種清楚的作品生產邏輯，避免主題詞跨頁污染、模板誤掛與共用核心膨脹。

機器可讀的頁面登記表位於 `assets/theme-registry.js`。新增或移動分類時，先改登記表與本文件，再改頁面資料。

## 2. 五層判斷順序

分類時依下列順序判斷，越前面的條件優先級越高：

1. **成品用途**：是旅拍、雜誌封面、住宅生活廣告、平面設計、公仔或人物寫真？
2. **生成模式**：是參考照片重建真人、插畫媒材轉換、物件轉換，還是已完成照片的 Stage 2 設計？
3. **主要場景敘事**：地點旅途、棚拍、住宅生活、文化空間、奇幻世界或節慶事件？
4. **服裝／文化來源**：漢服、和服、韓服、婚紗、晚宴、偶像、學園或幻想服裝？
5. **攝影語言**：構圖、鏡頭、光線與色彩只用來細化分類，不得單獨推翻前四層。

### 2.1 一主責、可加標籤

每個素材只能有一個 primary owner。可以有多個描述標籤，但不能同時把同一個模板放入兩個頁面的 preset pool。

- `owner` 決定模板放在哪一頁。
- `family` 決定頁面契約、核心組合與驗證方式。
- `tags` 可以描述材質、季節、色彩或攝影語氣，但不改變 owner。

例如：穿和服在京都街道拍攝，主要敘事若是「旅行地點」，歸入 `travel.html`，和服只作為服裝標籤；若主要敘事是「和服結構與日本庭園肖像」，才歸入 `japanese-kimono.html`。

## 3. 共用核心邊界

共用核心只處理跨頁都必須成立的機制：

- 參考照片身份與臉部幾何保留
- 真人頭頸肩脊椎與身體比例
- 鏡頭重建與頭身比例
- 全局光線、膚色與曝光一致
- 姿勢自然性、畫面淨化、輸出品質

以下內容不得直接加入 `assets/core-prompt.js` 的共用身份／骨架／負面核心：

- `adult East Asian woman`
- 長黑髮
- 特定唇色
- 特定胸腰比例
- `no dramatic cinematic lighting`
- `no animal ears`
- `no excessive pink`

這些若確實屬於某個專題，只能放在該頁的局部資料或該模板的 scoped prompt；沒有主題需求就不要輸出。身形選項的控制文字仍由各頁 `bodyShape`／`BODY_SHAPES` 負責，不寫入身份核心。

## 4. 頁面歸屬規則

### 真人參考照片頁

- **寫真旅拍**：真實地點與旅途事件是主角；地點與旅拍情境優先。
- **雜誌棚拍**：封面、棚拍、時裝、美妝或精品人物主視覺是主角。
- **Luxury Lifestyle**：住宅空間、家具尺度與生活互動是主角。
- **現代寫真攝影**：人物狀態、姿勢、現代生活光線與服裝肖像是主角；不要求住宅品牌敘事。
- **西式婚紗藝術寫真**：單人新娘、西式婚紗結構、頭紗與婚紗攝影是主角。
- **中式婚嫁藝術寫真**：中式婚服形制、婚嫁儀式、織金刺繡與喜堂／古宅場景是主角；不以西式婚紗或教堂長頭紗作為正向主體。
- **氣質名媛宴會**：晚宴、紅毯、珠寶與社交場合是主角。
- **韓系氣質偶像風**：舞台、機場、街頭偶像與城市時尚是主角。
- **節慶美學寫真**：明確節日事件、季節文化、節慶道具與主題造型是主角；生日等單張候選素材先記錄，不自動擴充選項池。

### 文化服飾頁

- **中式古典美學**：漢風、盛唐、宋韻、唯美古風與改良漢服；不放仙俠法術或科技幻想。
- **日本和服美學**：和服、帶結、日本織物、庭園、町家與日本季節文化。
- **韓國韓服美學**：韓服、襖裙、韓屋、宮廷長廊與韓式季節文化。

### 世界觀與媒材頁

- **幻想廣告**：奇幻材質與非現實世界觀形成品牌廣告。
- **中式仙俠**：仙門、法器、靈獸、御劍與東方奇幻世界觀。
- **日式異世界**：日式輕小說／JRPG 陣營與真人寫實角色轉換。
- **花仙子**：花卉服裝、翅膀、蝴蝶與花園精靈感。
- **動漫人物美圖**：插畫、賽璐璐與動漫媒材轉換。
- **神話古文明女神**：希臘羅馬、敦煌與古文明女神史詩語言。

### 非一般人物攝影頁

- **公仔系列**：公仔、模型、包裝與展示物；不套真人頭身契約。
- **店家活動廣告**：店家活動資訊、商品／服務主視覺與後製文案。
- **編輯視覺設計**：輸入已完成照片後做封面、人物卡、海報、寫真書或旅遊平面設計；不得重畫人物。

## 5. 常見邊界案例

| 素材特徵 | 正確歸屬 | 判斷理由 |
|---|---|---|
| 沙發、咖啡桌、床上 | Luxury Lifestyle 或現代寫真 | 若住宅品牌與家具尺度主導，選 Luxury；若人物姿勢與生活狀態主導，選現代寫真 |
| 和服在京都街道 | 寫真旅拍 | 地點與旅途故事優先，和服是服裝標籤 |
| 和服在日本庭園棚拍 | 日本和服美學 | 和服結構與日本文化空間優先 |
| 黑色高級棚拍 | 雜誌棚拍或現代寫真 | 黑色本身不是犯罪或恐怖分類；看是否為封面棚拍或人物生活肖像 |
| 床上姿勢 | 現代寫真 | 床景只是場景，重點仍是人物、姿勢與生活攝影語氣 |
| 豪宅沙發加咖啡杯 | Luxury Lifestyle | 空間、家具與生活道具共同形成住宅廣告敘事 |
| 深色光影 | 依原主題 | 不能因為暗色就自動歸入犯罪、恐怖或心理驚悚 |
| 完成照片加字體與版面 | 編輯視覺設計 | 這是 Stage 2 平面設計，不是重新生成照片 |
| 紅色燈飾與古典服裝 | 節慶或中式古典 | 若節日事件主導，選節慶頁；若服裝朝代主導，選中式古典 |

## 6. 新素材入站流程

1. 讀取圖片與對應文字檔，建立來源索引；私人來源不得放入 Git。
2. 先寫一句「這張圖最主要想完成什麼作品」，不能先看單一服裝詞。
3. 依五層判斷順序選一個 primary owner。
4. 把素材拆成場景、服裝、姿勢、構圖、光線、色彩、配件與故事欄位。
5. 對照 owner 頁面的 allowed／forbidden，刪除不相符詞，不把整段原始咒語直接貼入共用核心。
6. 若能形成完整作品概念，才建立一鍵模板；模板必須一次回填所有該頁控制項。
7. 執行 `check-theme-classification.mjs`、`check-ui-flows.mjs`、`validate-preset-refs.mjs` 與隨機稽核。

## 7. 模板歸屬與共用素材

模板名稱可以相近，但資料只能由 owner 頁面持有。若同一概念需要跨頁使用，建立兩個主題化模板，各自改寫成該頁的語言，不共用一段未經分類的長 Prompt。

共用核心的任何修改都必須先對照 `docs/core-prompt-contract.md` 與 `docs/shared-protection-core.md`。主題擴充優先放在頁面資料，不以「全站都可能用到」作為把專題詞塞入核心的理由。

## 8. 驗收標準

- 每一個正式工具頁在 `assets/theme-registry.js` 有且只有一筆登記。
- 每一個模板有明確 owner，且只存在於 owner 頁面的資料池。
- 正向 Prompt 不出現其他頁面的專題詞，除非它是明確的自訂輸入。
- 共用身份、臉部幾何、真人骨架核心不含專題人物外觀、特定唇色、特定身材或單一色彩禁令。
- UI 標籤、實際 radio value、資料物件、模板與生成函式彼此一致。
- 靜態檢查、DOM 順序、模板引用、Prompt 預覽與 100x 隨機稽核全部通過。
